# 能力边界（BOUNDARIES）

> 这份文档写**做不到什么**和**会在哪里坏**。
> 功能怎么用见各子系统文档；这里只回答"边界在哪、坏了怎么认、怎么恢复"。
>
> 原则：**先把边界说清，再谈能力**。一份只说"能做什么"的文档，等于让使用者自己踩雷。
 > **最后核对**：2026-10-26（全仓库逐行梳理）。配套阅读：总纲 [ARCHITECTURE.md](ARCHITECTURE.md) · 索引 [../README.md](../README.md)。

---

## 1. 环境边界

| 维度 | 现状 | 含义 |
| --- | --- | --- |
| 操作系统 | **Windows 优先**（部分脚本有 POSIX 分支，但未系统验证） | 沙箱 ACL、`icacls`、`.bat` 启动器、SnowLuma 都按 Windows 写 |
| DSH 版本 | 实测 `0.2.1-rc.2`；协议自 `0.1.2-alpha.1` 起 | 更早版本不兼容；升级后先跑 `npm run verify:adaptation` |
| Node | `>= 22.13.0` | 插件用 `fileURLToPath`、顶层 await、`fs.cpSync` 等 |
| SnowLuma | 第三方专有运行时，**不随仓库分发** | 本程序只探测/打开，不安装、不部署、不代扫码（EULA §5.4） |
| 语音引擎 | 仓库外的 `voxd` | 本地包需要 NVIDIA 显卡（6G 显存以上）与 `gsv` 依赖；没装就只会降级成文字 |
| 桌宠 | 仓库外的 Electron 工程 | 不装就不影响 QQ/B站，只是没有桌宠载体（目的机制回落 QQ） |
| 网络 | 本机回环 + 出网（QQ/B站/搜索） | 控制台与插件 API 都只接受回环；出网必须过 SSRF 校验 |

**不支持**：多用户/多租户、远程访问控制台（要远程请 SSH 隧道并自担风险）、Linux/macOS 的正式支持、
把 SnowLuma 打包进发行版。

## 2. 能力矩阵

图例：✅ 能做并已验证 · 🟡 能做但有条件 · ❌ 不做（有意） · 🚧 未做

### 2.1 QQ 侧

| 能力 | 状态 | 边界 |
| --- | --- | --- |
| 收群/私聊消息、白名单过滤 | ✅ | 白名单为空且 `allowAllWhenEmpty=false` 时**谁都不响应** |
| 发文本/引用回复/分条 | ✅ | 单条 >500 字 → 400；一次最多 8 条；超频 → 429 |
| 发表情包（收藏自定义表情） | ✅ | 一条消息只能一张表情，不能与文字同气泡 |
| 发图片/动图 | ✅ | 单条 8MB / 64MP / 5 张（`socialV2.media`） |
| 发合并转发内容 | ✅ | 只能**看**转发（`qq_get_forward_msg`），不能构造转发发出 |
| 拍一拍 | ✅ | 群聊需 targetUserId；有频率限制 |
| 语音（语音库 / 现场合成） | 🟡 | 默认关；需要引擎；受频率与字数上限；合成失败**不会**假装发出去 |
| agent 提问 / 工具审批转 QQ | ✅ | 超时按 `questionTimeoutMs` 失效 |
| 主动找主人（目的机制） | ✅ | 安静时段/每日上限/额度/专注模式/好友关系多重闸门 |
| 主动搭话（二代 `proactive`） | ✅ | 与目的机制是**两套**独立机制，可分别关 |
| 潜水/沉睡前观察 | ✅ | 说"要睡了"之前必须真的等够 5 分钟静默，桥接会校验 |
| 对话收尾 | ✅ | 对方明确在提问/求助时**拒绝**收尾 |

### 2.2 B站 侧

| 能力 | 状态 | 边界 |
| --- | --- | --- |
| 看视频、打分、收藏、评论/回复 | ✅ | 受四本账额度、作息窗口、鱼群守则约束 |
| 发动态 / 编辑动态 / 发图 | ✅ | 有额度与间隔；内容过身份闸与脱敏 |
| 分享视频到 QQ | ✅ | 用文本链接卡（小程序卡在 QQ 侧已下架） |
| 回私信、直播间监听 | 🟡 | 默认关，需配置；直播间挂了会一直重挂 |
| 一键抓取偏好（读主人的 B站） | 🟡 | 用**独立的只读凭据**文件，绝不用于发评论 |
| 扫码登录 | ✅ | 二维码轮询；cookie 过期要重扫 |
| 风控/验证码 | ❌ | 遇到就失败并记录，不会尝试绕过 |

### 2.3 记忆 / 人格 / 额度

| 能力 | 状态 | 边界 |
| --- | --- | --- |
| 衰减记忆卡（会遗忘、有清晰度） | ✅ | 容量 80/90/100% 三档告警；可自动压缩到 90% |
| 全量记忆卡（永不遗忘） | ✅ | append-only；**不进提示词**；默认 10GB 上限只告警不删 |
| 三场景共享一张卡（QQ/B站/桌宠） | ✅ | 每条记忆带 `scope`；B站 只取 `bili/shared`，`scope=pet` 默认不进 B站 |
| 多角色（人格+记忆+B站 账本整包切换） | ✅ | 切换是整包换，不是只换提示词 |
| 角色自动存档/回档 | ✅ | 每 6 小时一份，滚动保留 |
| 每日额度（QQ/B站/其他/总额） | ✅ | 80% 每天提醒一次；100% 停唤醒/评论（不硬杀正在进行的回合） |
| token 看板（逐轮/逐群/峰谷） | ✅ | 精度取决于 DSH 投影；价目表可自定义 |

### 2.4 语音 / 桌宠

| 能力 | 状态 | 边界 |
| --- | --- | --- |
| 语音库发送 | ✅ | 白名单音频格式；路径必须在本库内（`safeJoinLibrary` 含 realpath 防 symlink） |
| 本地 TTS 现场合成 | 🟡 | 需要引擎；120 字上限；超时 60s；失败 502 |
| 本地/云端路由切换 | 🟡 | 桌宠每次合成前重读；**桥接要重启**（语音配置在启动时读进内存） |
| 桌宠文本/语音对话 | ✅ | 需要桌宠在线；历史按角色隔离；**没有麦克风输入（ASR）** |
| 桌宠即时气泡 + 回复按钮 | ✅ | 气泡只有文字；语音由对话框或气泡之一播放（唯一媒体所有者） |
| 目的载体 = 桌宠 | ✅ | 与 QQ 互斥；30 秒内生效；桌宠离线默认回落 QQ |
| 专注模式 | ✅ | 桌宠右键/托盘/设置页三处开关，单一真相文件；停了自动搭话，不停用户主动对话 |

## 3. 失败模式与恢复

| 症状 | 最可能的原因 | 怎么认 | 恢复 |
| --- | --- | --- | --- |
| QQ 完全没反应 | 桥接没跑 / SnowLuma 没登录 / 白名单空 | 控制台「运行总览」看桥接与 SnowLuma 状态 | 启动桥接 → 登录 SnowLuma → 填白名单 |
| 桥接起来了但收不到消息 | SnowLuma 端 WS token 与 HTTP token 是两个值；或端点自愈覆盖了手写地址 | `bridge.log` 找 401/连接失败 | 用控制台「端点自愈」跟随，或填对 token |
| 回复卡在"繁忙" | DSH 回合没结束 / 会话退役异常 | 控制台会话列表看 pending | `/reset` 该会话，或重启桥接（会重建会话） |
| agent 只会说话、不调用工具 | MCP server 没挂上 / 工具被 `qq-tool-restrict` 拦 / 单个工具开关关了 | 设置页工具开关；DSH 的 MCP 配置 | 重装 preset（`setup-dsh.mjs`）→ 重启 DSH |
| 工具调用 403 | 会话 token 失效、模式不允许、AI 已暂停、额度到 100% | 返回体的 `error` 文案 | 按文案逐项放开 |
| 设置页 401 | 没走 DSH 登录态 | 浏览器直接访问插件 API | 从 DSH 界面进 |
| 桌宠连不上 | 桌宠没启动 / DSH 端口漂移 / host.json 没重写 | `~/.dsh/surfcore/pet/host.json` 的 baseUrl | 插件每 2 分钟重写；重启 DSH 后重开桌宠 |
| 桌宠 401 | 令牌文件被删/权限变了 | `pet/host-token` 是否存在 | 重启 DSH 重新生成 |
| 语音 502 | 引擎没启动 / 端口占用 / 依赖缺失（gsv） | 设置页语音页状态条 | 启动对应包；看 `state/voice-packs/` 日志 |
| 语音有回音 | 气泡与对话框同时播 | 两个窗口都开着 | 已修：对话框可见时语音只由对话框播 |
| B站 什么都不做 | 不在作息窗口 / 额度用尽 / 账号未登录 | 设置页 B站 状态与 `quota.json` | 调窗口/额度；重新扫码 |
| B站 评论失败 | 风控 / 验证码 / 内容被拦 | 工具返回的 code 与 message | 人工处理，程序不绕风控 |
| 记忆卡不更新 | inbox 没写 / 插件没跑 / 预算裁掉了新小节 | `memory-inbox.jsonl` 是否有新行 | 看插件日志；确认新小节的 priority 高于会先被裁的段 |
| 记忆卡越用越贵 | 注入块太大 | `memory-card-prompt-*.md` 字数 | 调 `injectMaxChars` / `maxChars` |
| 改代码热重载不生效 | 插件引用的是 `src/*.js`，热重载只重载插件自己的文件 | 现象：改了引擎行为没变 | 重启 DSH；改 `src/memory-card.js` 还要 bump `?rev=` |
| DSH 升级后全崩 | `app.asar` 补丁被覆盖 / 协议变了 | 工作区列表空、插件不激活 | `npm run guard:check` → `npm run verify:adaptation` → `npm run test:audit` |

## 4. 安全边界：承诺与不承诺

**承诺**

- 群友**物理上**碰不到本机：仿真会话的工具面是白名单、fail-closed，本地执行能力全部被 `restrict`。
- 发送**必须**命中白名单；不带"管理员例外"这种后门。
- 不外发没有授权的东西；出机清单写在 `LICENSE`。
- 不可逆删除不做：清理一律先隔离到 `_backups/` 或 `~/.dsh/_quarantine/`。
- 密钥不落日志、不进回复；配置读给 UI 时脱敏。

**不承诺**

- **提示注入的语义层防护不是 100%**：正则与规则是启发式，能挡"路径/凭据/联系方式"这类硬模式，
  挡不住"用隐喻把信息编码出去"。真正的边界是工具面与白名单，不是提示词。
- 用户如果自己把 DSH 暴露到局域网/公网，本程序不负责那层安全（控制台只做回环校验）。
- 本机已被入侵（同用户权限的恶意进程）时，文件级防护（ACL/0600）只能提高成本，不能保证。
- B站 风控、QQ 风控、SnowLuma 的稳定性都不在本程序控制范围内。

## 5. 资源边界

| 资源 | 现实量级 | 说明 |
| --- | --- | --- |
| 磁盘（语音包） | 几百 MB ~ 数 GB | 用户素材，占 `state/` 的绝大部分 |
| 磁盘（TTS 缓存） | 几十 MB | 按内容 sha1 复用 |
| 磁盘（记忆） | 衰减卡几十 KB；全量卡按条数线性增长 | 全量卡默认 10GB 上限只告警 |
| 上下文 | 注入块 2.2k / 2k 字 + 未读 + 目的提示词 | 三个旋钮：`injectMaxChars`、`context.*`、`promptMaxChars` |
| 请求频率 | QQ 发送 8/分钟、60/小时；语音 2/分钟、10/小时 | 超限直接拒，模型会改策略 |
| 会话数 | 每个 QQ 会话一个 DSH 会话 | 群多时 DSH 会话数线性增长（可用「重置」回收） |
| 内存 | 桥接常驻数百 MB 量级 | 单文件 `social-v2.json` 约 400KB，启动时全量读 |

## 6. 数据出机边界

| 会出机的数据 | 去哪 | 怎么关 |
| --- | --- | --- |
| 群聊文本（拼进提示词） | DeepSeek API | 关掉对应模式 / 不给白名单 |
| 黑话词条 | 搜索后端（DeepSeek 搜索或 Bing） | `slang.autoResearch=false` 或 `webSearch.provider=bing` |
| B站 公开内容（视频/评论） | 本机模型调用 | 关 `biliBridge.memory.enabled` |
| 主人邮箱/私信内容（若启用） | 模型调用 | 默认不进记忆卡（`blockPrivateMessages`） |
| 桌宠对话 | 本机模型调用 | 关桌宠对话或 `pet.chat.enabled=false` |

**不会出机**：cookie/令牌（只在本机文件里）、`config.json`、`state/`、`~/.dsh/surfcore/` 里的原始文件。

## 7. 必须由人做的事（程序有意不做）

1. 安装/登录 SnowLuma（扫码）。
2. 安装语音引擎与语音包（下载、显卡依赖）。
3. B站 扫码登录 / 续期。
4. 处理 B站/QQ 的风控与验证码。
5. DSH 升级后跑体检三件套（`guard:check` / `verify:adaptation` / `test:audit`）。
6. 决定什么时候公开仓库（先跑 `npm run privacy-scan:strict`）。

## 8. 已知未做 / 结构性问题

| 项 | 性质 | 备注 |
| --- | --- | --- |
| `src/bridge.js` 15,000 行单体、控制台 126 条路由一条 if 链 | 架构债 | 拆分需要单独一轮 + 完整回归 |
| 双进程写同一份 `config.json`，无跨进程锁 | 已知风险 | 原子写保证不写坏，极端情况下后写覆盖先写 |
| 插件 → 核心用相对路径 + `?rev=` 缓存破坏 | 耦合 | 有 `test-core-rev-sync.mjs` 兜底 |
| `config.example.json` 缺四段 | 模板债 | 见 DATA-AND-CONFIG §1.13 |
| 桌宠协议只有 `version: 1`，无版本协商 | 边界 | 单机可接受；跨版本升级要先看 PET 文档 |
| 语音对话无麦克风输入（ASR） | 未做 | 目前是"文字输入 + 语音回复" |
| 本地语音包缺 `gsv` 时的报错偏技术化 | 体验 | 需要看 `voice-packs` 日志 |

最新的风险状态以 `docs/RISK_REGISTER.md` 为准；这里只列"结构性"的那几条。
