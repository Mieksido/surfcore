# 限制失败的用户可见性

- **日期**：2026-10-31
- **反馈截图**：`qq_send_message` 返回 `发送失败：发送频率超限，请稍后再试`，用户不知道是哪个设置、怎么改。
- **根因**：桥接的发送频率检查只回一句泛化错误；没有 code/setting/current/limit；也没有进错误报告。
- **修法**：
  - 新增 `sendRateLimitInfo()`：给出具体配置项、当前值、上限、重试时间、设置路径；
  - 所有 send-message / send-burst / send-poke / send-sticker / 单条发送的频率检查统一走它；
  - 失败写 L1 gate event `limit`（不弹 L2/L3）；
  - 概览新增「错误报告 / 限制提醒」卡：显示原因、设置位置、当前/上限；
  - 用户可点「去改设置」跳到 QQ 页，或「知道了（本限制提醒）」确认；
  - 鱼群保护、Token 每次发送上限也写 L1 报告。
- **设置路径**：QQ → 高级设置 → 发送与节奏 → 每分钟/每小时最多发送。
- **验证**：`node scripts/test-limit-report.mjs`；`npm run test:audit`。
- **残余**：单条字数/条数等参数错误仍是直接错误，尚未全部进 L1 报告；后续可统一到 limit event。

## 追加：1 小时去重 + 永久不再显示

- 同一 `code + key + setting` 的 L1 限制提醒最多 1 小时一条；
- 记录写入 `state/limit-mutes.json` 的 `lastAt`，桥接重启也不重复刷；
- 概览错误报告提供「永久不再显示」，写 `muted[code]`；
- 已静音的 code 不再生成 gate event；
- 用户确认按钮仍保留，可选择只确认本次而不永久静音。
