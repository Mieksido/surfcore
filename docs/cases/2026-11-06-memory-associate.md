# 联想（第 6 件）：让她在醒来时顺带想起一件快淡忘的旧事

- 日期：2026-11-06
- 范围：`src/memory-associate.js`（新增）、`src/bridge.js`（预取 / 提示词 / 冷却 / 控制台预览）
- 上游参考：B 项目 `life-loop.js` 的联想链（调 memory-rag 的 `/associate`）

## 为什么改路线

B 的联想挂在生活回路上：定时向 `/associate` 要「和最近话题相关的旧事」，挑中了就**主动发一条消息**。
那是「自主生活」的一部分，本仓库刻意没搬（`purpose-engine` 已有近似能力，多一个定时器只会让她
半夜忽然发消息）。所以这里换的是通路，不是目的：

| | B | 这里 |
| --- | --- | --- |
| 什么时候想 | 定时器，到点就发 | 只有本来就要说话的那次唤醒，顺带一层薄注入 |
| 想什么 | 「和最近话题相关」 | **快淡忘的**（R 落中间段），不是最相关的 |
| 怎么用 | 主动发一条 | 只说一句「搭不上就别硬提」，是否提由她判断 |
| 会不会打扰 | 会（主动消息） | 不会（不额外发消息） |

「快淡忘的」是这一件和记忆检索的分界线：检索回答「对方提到的那件事是什么」，
联想回答「她自己的记忆里，有什么正要从指缝漏掉」。按 R 挑是间隔重复的思路——
R 太高（刚聊过）不必提，R 太低（已经想不起来）提了也接不上，中间那一段提一句能续上。

## 通路安全

1. **唤醒路径是同步的**：不能在 `buildWakePromptV2` 里 await 一次检索。
   预取在 `scheduleWakeV2` 排唤醒时异步踢一脚（每会话 5 分钟节流），提示词只读缓存（10 分钟有效）。
   没赶上就这一轮不带 —— 联想没有也照样能醒。
2. **只读 / 消耗分离**：`buildWakePromptV2` 一次唤醒会被调两遍，`associateLine` 只读；
   记冷却的 `associateSettle` 放在 `api.sessions.prompt` 被接受之后（和约定、建议、星图同一口径）。
3. **不重复**：对方说「还记得那次…」时由第 1 件检索负责，此时联想直接让步（两边不同时注入）。
4. **不影响主路径**：检索失败 / 索引缺失 / 状态文件坏 JSON 一律静默跳过，绝不冒异常。
5. 状态文件跟角色目录走：`memory/memory-associate.json`，原子写、`0600`。

## 挑谁（实测数字）

`clarity=clear`、重要度 50 的记录：R 在头 20 多天被卡面上界压住（0.75），之后按 S·D 衰减——
120 天约 0.46、400 天约 0.27、1200 天已跌破 0.2。默认区间 `[0.2, 0.65]` 大致对应「一个多月到一年多
没再提过」的旧事；保护类（钉住 / 最初 / 主人重要）不淡忘，因此永远不参与。


反向验证：把 `associateLine` 改成「读即删」→「连建两遍都带」变红；把 `associateSettle` 挪进
`buildWakePromptV2` →「还没接受就不能清」变红。两次都改回并重跑全绿。

控制台排查：`POST /api/memory/associate/preview {"key":"private:<QQ>"}` 立刻跑一次预取并返回
「这轮会想起什么」（不写冷却），改 `rMin/rMax` 时用它比较几组区间。
