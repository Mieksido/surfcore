# 2026-10-28 · 语音包「显示安装完成」但只下了 490KB

## 现象

- 用户点「安装（1.9GB）」→ 等很久 → 界面进度条旁写「**安装完成**」；
- 但卡片仍是「1.9 GB · 端口 8765 · **未安装**」；
- 打开目录只有 **490 KB / 82 个文件 / 11 个文件夹**（只有代码，没有 `models/`、`vendor/`）；
- 目录属性还带「只读」。

## 根因（三处叠加）

1. **前端谎报完成**：`client.js` 里
   `await poll(id); setMsg("安装完成")` —— `poll()` 超时（240×1.5s≈6 分钟）或失败返回后，
   调用方**无条件**把文案写成「安装完成」，把 `poll` 里刚设的失败原因覆盖掉了。
2. **后端没有完整性校验**：`install()` 跑完 postInstall 就标 `完成`。
   当 `fetch-models.mjs` 中途失败/超时（1.84GB 从 GitHub 拉，国内很容易断），
   进程内只留下解压出来的代码目录，却仍然走"完成"分支。
3. **解压后没清只读**：GitHub archive 解压出来的文件带只读属性，
   后续复制 `config.toml`、写 `models/` 可能失败；用户看到的目录属性「只读」就是这个。

## 修法（v0.6.13）

1. `poll()` 返回状态（`ok` / `failed` / `timeout`），前端按状态写文案：
   完成 / 失败（带原因）/ 还没完成（可重试）；
2. `install()` 结束后做**完整性校验**（`verifyDirs`）：
   - 本地包必须同时有 `models/`、`vendor/GPT-SoVITS`；
   - 云端包必须有 `models/`；
   - 缺任何一个 → `失败`，错误信息写清"缺什么、怎么重试、可先删目录"；
3. 解压后执行 `attrib -R "<dir>\*" /S /D` 去掉只读；
4. 后置脚本**缺失**不再静默跳过，直接报「安装包缺少 xxx」；
5. 拉模型/装依赖时**解析子进程输出的百分比**，进度条从卡死的 99% 变成 90→99 递增；
6. 失败信息里带子进程最后 600 字符日志，便于定位是网络还是脚本错误。

## 验证

- `npm run test:audit` 77/77；插件 `npm test` 通过；
- **未验证**：真实网络下 1.84GB 断点/超时场景（手头没有低带宽环境），
  只验证了"缺目录会报失败"这条判定逻辑。

## 遗留

- 下载 1.84GB 没有断点续传：中断就得从头来。后续可以支持 Range 续传，或把 vendor 拆成多个小包；
- 国内拉 GitHub Release 慢/断是常态，考虑加镜像源（用户可配）。
