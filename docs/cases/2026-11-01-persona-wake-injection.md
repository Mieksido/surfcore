# 唤醒只给「指针」不给人格卡：她不知道自己是谁

## 现象

- 用户看到什么（原话尽量保留）：群里让她"假装我是大鳄鱼"时，她**凭感觉瞎答**（"凑过去喊一声大鳄鱼"），
  而不是照人格卡说话。把那次会话的日志翻出来看：唤醒消息一共 7303 字，里面有身份、来源判断、
  Token 商量、表情、收尾、消息快照……**唯独没有一个字的人格卡**。全文搜「一、我是谁」= 0 次。
  桥接二代模式只发了这一行：`【当前角色】大鳄鱼（完整角色卡请调用 qq_get_prompt 查看）`。
- 复现步骤：
  1. `reserved2` 模式下任意会话被唤醒；
  2. 打印 `buildWakePromptV2(key, reason)` 的返回值 → 看得到指针，看不到人格卡正文；
  3. 这个模型**不会**去调 `qq_get_prompt`（见下面证据），于是人设永远进不了上下文。
- 影响面：所有 `reserved2`（二代仿真）会话；**不丢数据**、不报错、不能自己发现；
  影响的是"她像不像那个人"——最核心的产品体验，而且是最安静的那种坏。

## 根因

- 代码位置（文件:行）：
  - 旧唤醒提示词：[`src/bridge.js:13518`](../../src/bridge.js#L13518) 只有 `roleLine` 指针；
    [`13601`](../../src/bridge.js#L13601) 注释写明「二代模式不自动注入完整角色卡（让 AI 调 qq_get_prompt）」。
  - 人格卡正文的**唯一出口**：[`src/bridge.js:5991`](../../src/bridge.js#L5991)，在 `qq_get_prompt` 的 HTTP 处理里。
    `currentRoleHintV2` 全仓库只有这一处调用。
- 问题链条：唤醒提示词给了一个"指针"，把"取人设"的责任交给模型的**自愿工具调用**；
  而模型在高频、低激励的唤醒里不会为一个"我已经知道的事"付一次工具调用。
  → 人设从未进入上下文 → 它只能靠语气词和身份底座硬撑。
- 为什么不报错：整条链路"成功"了（消息投递 ok:true、模型也回了话），只是内容缺一块。
- 为什么之前没发现：**没有任何测试断言"唤醒提示词里有人格卡"**。提示词内容不进单元测试，
  只能靠人肉看日志——而日志里那行指针看起来"合理"，很容易被认为"设计如此"。
- 证据（实测，不是推测）：
  - `state/tool-calls.jsonl` 共 **1830** 次工具调用，`qq_get_prompt` 只有 **10** 次，
    全部集中在 2026-10-31 的四个时间点（04:28 / 10:35 / 10:38 / 11:00）——像当天在调这个工具；
  - **2026-11-01 当天 0 次**（那天另有 24 次工具调用）。
  - 工具本身可用：`config.json` 里 `socialV2.tools.getPrompt = true`，不存在 403 死指针。

## 完整逻辑（给用户看的那一遍）

- **链路**：`sendWakePromptV2` → `buildWakePromptV2` 拼纸条 → `deliverPrompt` 排队 →
  `api.sessions.prompt` 投递给 DSH。人格卡正文只存在于 `qq_get_prompt` 这条旁路（模型主动调用才发生），
  两条路都从 `composePersonaLayers`（`src/persona-layers.js`）产出，但**唤醒这条路以前没调用它**。
- **机制**：这是"把决定权交给模型"的设计。它在 `reserved2` 里本意是省 token + 保持自主；
  但省掉的是"她是谁"这种**每轮都需要**的底座，不是"可以按需拉取"的细节。契约写错了层级。
- **爆炸半径**：1 个进程（QQ 桥接）× 所有 reserved2 会话 × **静默=3**。
  不碰用户数据、不碰密钥、每轮多花约 400 字符（本机卡 335 字符）≈ +5% 的唤醒 prompt。
- **取舍**：
  - **A1（采用）**：唤醒侧注入人格卡正文，和 `qq_get_prompt` 走**同一个组装函数**，
    不是手抄两份 → 改卡不会漂；`qq_get_prompt` 继续负责全量/场景/推荐值。
  - A2：两份都塞全卡——重复、且两份独立拼装迟早漂。
  - A3：删掉 `qq_get_prompt` 只留纸条——模型再也查不到场景语气/推荐值/工具列表。
  - B（人格分层 tone 模式）**这次不改**：`persona-identity.js` 已保证「tone/full 都带身份底座」，
    且 `composePersonaLayers` 只在**真的存在语气层**时才省核心。本机未拆语气层，行为不变，先不扩大改动面。
- **生效与重启**：只改 `src/bridge.js` → **重启 QQ 桥接**生效；不需要重启 DSH、不需要重装插件/MCP。

## 修法

- 改了什么：
  1. `roleHintForMode(mode, key, personaMode, opts)` 新增 `opts.personaOnly`：
     只返回人格卡正文，提前 return，不再拼管理员规则/B站简报/记忆卡（这些唤醒侧本来就有，重复拼会让同一段出现两次）。
  2. 新增 `personaWakeBlockV2(key)`：唤醒侧的「随身身份证」= `【当前角色】名字` + 人格卡正文 + 一行"全量可查"指针。
     组装失败时**降级**为旧指针并记日志，不炸唤醒。
  3. `buildWakePromptV2` 与 `buildWakeReminderPromptV2` 都改用 `personaWakeBlockV2(key)`。
  4. 同步改掉 `13601` 那句已过时的注释（"不自动注入完整角色卡"）。
- 为什么选这个方案：不改协议、不改工具、不改状态文件；复用现成的 `role.maxInjectChars` 预算
  （默认 6000 字，本机卡 335 字）；与 `memoryCardLine` / `adminLine` / `biliLine` 完全同构。
- 回滚方式：`git revert <本提交>` → 重启桥接，即回到"只给指针"的旧行为。

## 验证

- 自动化：`npm run test:audit` → **111/111**（新增 `scripts/test-persona-wake-injection.mjs` 钉住接线与分层契约）。
- 离线组合验证（真实角色卡）：

  ```
  sum of raw files: 269
  full  -> chars: 335 layers: {"identity":50,"core":207,"tone":0,"scene":0,"daily":74}
  tone  -> chars: 335 layers: {"identity":50,"core":207,"tone":0,"scene":0,"daily":74}
  tone 里还有身份底座吗: true
  ```

  说明：本机未拆语气层，tone 会兜底回核心（符合设计），身份底座两种模式都在。
- 失败路径：人格卡组装抛错 → `log` 一行 + 降级回旧指针，唤醒照常发送（不会因为卡坏了叫不醒她）。
- 没验证到的部分（老实写）：
  - **没有重启桥接**，所以线上还没观测到 `lastWakePromptMeta.role > 0`；
  - 没验证真实模型的行为改善（要等一次真实唤醒后看日志/遥测）；
  - 插件测试有 1 项**既有**失败 `plugins/surfcore/scripts/test-ui-contrast.mjs:16`
    （断言弹窗必须写死深色背景，而 dev.5 主题收口已改成跟随主题 `var(--qbw-surface)`），
    与本批无关（本批未改任何插件/UI 文件），未擅自修。
