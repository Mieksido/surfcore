# 人格卡住址规则误报：把“住址、联系方式”当成地址值

日期：2026-11-03

对应：GitHub issue #7

## 现象

新建角色或编辑人格卡，填官方模板原文也保存不了：

```json
{ "ok": false, "error": "人格卡命中密钥/密码/身份证/住址规则，拒绝保存" }
```

触发句：

```markdown
- 私信、密码、令牌、住址、联系方式绝不跨平台搬运。
```

这是在声明“不搬运隐私”，却被当成地址泄露。

## 根因

`plugins/surfcore/lib/privacy.js`：

```js
{ kind: 'address',
  re: /(?:住址|家庭地址|收货地址|住在|地址是|地址：|地址:)[^\n。；;]{4,60}/g,
  label: '住址', severe: true },
```

关键字后只要跟 4–60 个非 `。；;换行` 的字符就算地址。  
终止字符集没有顿号 `、` 和逗号 `，`，于是：

```text
住址、联系方式，绝不跨平台搬运
→ 被当成“住址：联系方式，绝不跨平台搬运”
```

`characters.js` 的新建/编辑都把 severe PII 当拒绝条件，所以两条路径同时被挡。

## 修法

给关键字后加负向前瞻：

```js
{ kind: 'address',
  re: /(?:住址|家庭地址|收货地址|住在|地址是|地址：|地址:)(?![、，,])[^\n。；;]{4,60}/g,
  label: '住址', severe: true },
```

含义：

```text
关键字后面如果是 、 / ， / , → 这是枚举，不是地址赋值
```

保留真实地址：

- `收货地址：北京市…`
- `家庭地址: 广州市…`
- `地址是上海市…`
- `我家住在海淀区…`

## 没有做

- 没有改 `PRIVATE_TOPIC`；它仍把“住址”当敏感话题，记忆侧可能整行丢弃，但人格卡保存只看 PII/secrets。
- 没有在错误信息里回显命中片段；避免把 PII 再打给用户/日志。
- 没有改其他 PII 规则（真名/位置/手机号）。
- 没有补官方模板文件；当前仓库没有 `examples/character/persona.md`。

## 风险

- 负向前瞻会放过“住址、北京市…”这种顿号后接真地址的写法；但这更像枚举，需人工判断。
- 规则放宽可能漏掉没有冒号/系动词的地址（如 `住址 北京市…` 仍会命中，因为空格不是顿号/逗号）。
- 隐私规则是安全边界，必须同时保留真实正例测试。
- `PRIVATE_TOPIC` 仍可能让含“住址”的普通记忆行被丢弃；这是另一条规则，未在本批处理。

## 验证

```text
node plugins/surfcore/scripts/test-privacy.mjs
npm run test:audit

```
