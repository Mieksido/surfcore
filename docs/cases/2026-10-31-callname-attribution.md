# 2026-10-31 · 主人被叫成对象的「琳琳」——称呼没有按人归属

## 现象

主人和 bot 私聊，被叫成「琳琳」；「琳琳」是主人对象在另一个私聊里让 bot 用的称呼。
用户问：是不是和「白名单/补唤醒」同一个 bug？

**不是。** 白名单那条是「会话被拒绝 / 积压不唤醒」；这条是「**称呼/记忆没有归属**」。

## 根因（两处，互相叠加）

1. **私聊没有「当前对方希望被叫」的注入**：设置页的「称呼」存在对齐表里，但桥接**只在群聊**
   注入身份对齐块（`alignmentBriefBlock` 注释写明"私聊不需要"）；私聊提示里没有按当前 QQ 号取称呼，
   模型只能从别处猜。
2. **记忆卡里的私聊记忆不带说话人**：`recordLine()` 只对 `isSelf` 记录加 `speaker`，
   非主人的记录渲染成裸文本。于是「琳琳让我叫她琳琳」和主人的话混在同一段记忆里，
   模型把别人的称呼套到眼前的人身上。

## 修法

| 层 | 改动 |
| --- | --- |
| 纯逻辑 | 新增 `src/callname.js`：`pickPeerAlias(links, qq)` 按 QQ 号取称呼；`buildPeerAliasTag()` 生成只对当前会话生效的提示（含"不要套到别人身上"） |
| 桥接 | 私聊提示注入「当前对话对象（QQ x）希望被叫「X」」；只对 `private:*` 生效，群聊仍走身份对齐块；对齐表按 mtime 缓存 |
| 记忆卡 | 非主人记录渲染为 `说话人（私聊/群聊）：内容`；QQ 记忆注入块补规则"名字/称呼只属于说这句话的人，当前对话对象看发送者 QQ 号" |

## 验证

- 新增 `scripts/test-callname.mjs`：按 QQ 精确取称呼、不串号（只有 B站 的登记不会被 QQ 误用）、
  提示块禁止套用、记忆行带说话人/场景、桥接只对私聊注入；
- `npm run test:audit` 92/92；插件测试全绿。

## 教训

**"谁说的"必须跟着内容一起存、一起注入。** 记忆/称呼是跨会话共享的，缺少归属时，
模型会把 A 的偏好应用到 B 身上；这比"记错"更难发现，因为语气很像真的。
