> 本文件是「做什么、按什么顺序做、什么时候该放弃」的唯一权威。**改路线先改这里**，再动代码。
> 配套：开工动线见 [`../AGENTS.md`](../AGENTS.md)，踩坑见 [`PITFALLS.md`](PITFALLS.md)，交接见 [`HANDOFF.md`](HANDOFF.md)。

## 0. 路线守则（每次动手前读，按顺序执行）

1. **先分析**：写清「现象 → 根因 → 影响面 → 修法 → 验证方式」。分析没到能预判失败点，就别写代码，只做只读排查。
2. **再算收益**：每条候选路线列出四项——
   **收益**（用户实际得到什么）/ **成本**（人时 + 长期复杂度）/ **风险**（会不会破坏现有能力）/ **回滚难度**（能不能一步退回）。
3. **收益不佳 → 直接回退，换下一条路线**。沉没成本不是理由；「都写到这了」是最典型的错误信号。
4. **回退要干净**：用 git 回滚或隔离目录，禁止留下「半套新逻辑 + 半套旧逻辑」。
5. **不补屎山**：单文件 > ~800 行、或同一处出现 3 种写法/两套协议，就先拆再加。新代码必须让下一次改动更容易。
6. **不盲目跑探针**：`probe:*`、`setup-dsh.mjs`、`start*.bat`、会发 QQ 消息或写 `~/.dsh` 的脚本，先说明目的/预期/失败后果。
7. **一天一结**：当天结论写进 `HANDOFF.md`（做到哪、没验证什么）与本文（路线变没变）。**半天后的我不会记得，只会看文件。**

> 这几条是 2026-10-22 复盘时按外部建议定下的，不是装饰：上一次事故就是「没先分析影响面」+「在错地基上叠补丁」的代价。

## 1. 项目目标

### 1.1 必须达到（缺一不可）

| # | 目标 | 验收方式 |
| --- | --- | --- |
| M1 | QQ 消息稳定接入 DSH，agent 回复/工具审批/提问能回到 QQ | 真机发一条消息 → DSH 会话出现 → 回复回到 QQ |
| M2 | 群友**物理上**无法碰本机：无本地工具、发送强制白名单、回复审计 | `npm run test:audit` + `docs/guides/SECURITY_BASELINE.md` 清单 |
| M3 | 四个运行模式边界清晰，切换即生效，权限降级时旧会话自动重建 | 控制台切模式 → `state/mode.json` 与 DSH 设置一致 → 新会话用对 preset |
| M4 | 会话/配置/记忆**不丢**：任何清理都可回滚 | `_backups/`、`~/.dsh/_quarantine/`、`clean-dead-workspaces --apply` 前自动备份 |
| M5 | DSH 升级后能在一个版本内适配（协议/端口/preset 变化） | `npm run verify:adaptation`；升级后 `npm run test:audit` 全绿 |
| M6 | 插件装进 DSH 后不拖垮宿主：单个坏数据不能让服务起不来 | 见 `PITFALLS.md` #1 与 `scripts/patch-dsh-session-guard.mjs` |

### 1.2 底线（不可妥协）

- **不采集、不外发**群里没有明确授权的东西；数据出机清单以 `LICENSE` 为准。
- **不代替用户操作账号**：SnowLuma 只探测不部署、不代扫码（EULA §5.4）。
- **不可逆删除 = 事故**：删除只能通过「隔离 → 确认 → 手动清」三步。
- **密钥不落库、不落日志、不进回复**。
- **测不过不发布**：`test:audit` 红着就不许谈新功能。

### 1.3 可接受的妥协（明确写下来，避免越做越大）

- 一期只支持 Windows（本机 + 沙箱 ACL 的现实），跨平台放到「以后」。
- 控制台是单机回环 Web UI，不做多用户/远程管理。
- 人格/黑话等「软能力」允许启发式，不追求 100% 准确；边界靠硬规则（工具面/白名单/审计）而不是靠提示词。
- 探针脚本允许留在仓库里，但**默认不跑**，且必须能只读运行。

## 3. 路线候选（收益 / 成本 / 风险 / 回滚）

> 每次只挑一行做；开工前把该行的四列补全再动手。收益写「用户能感知的变化」，不要写「重构了 X」。

| 候选 | 收益 | 成本 | 风险 | 回滚 |
| --- | --- | --- | --- | --- |
| A. 会话日志自愈（插件启动时扫描身份错位并隔离） | 补丁失效（DSH 升级）时仍有兜底 | 中（需 zstd 解码或调用 DSH 内部 API） | 低（只读+隔离） | 删脚本即回退 |
| B. 控制台「健康自检」页（服务/端口/权限/备份一览） | 出问题不用再手工排查 27 分钟 | 中 | 低 | 页面隐藏即可 |
| C. 群聊图片/表情的可访问性兜底（CDN 失败重试与降级） | 掉图率下降 | 中 | 低 | 开关回退 |
| D. 文档自动化校验（README 版本/端口/命令与代码一致） | 防「文档比代码旧」 | 低 | 极低 | 删除校验脚本 |
| E. 多平台适配（贴吧 extension 落地；微博已明确不做，2026-10-23 移除占位） | 新场景 | 高 | 中（权限面扩大） | 保持 manifest 关闭 |

## 4. 人工决策点（我往往想不到最优路线，这些必须由用户拍板）

- 优先级取舍（A~E 先做哪个）。
- 涉及**对外发布/发送**的能力（新平台、主动私信、群管理动作）。
- 任何会**改变数据存放位置**的迁移。
- 安全边界的放宽（新模式、新工具面、白名单扩大）。
- 版本号与 Release 节奏。
