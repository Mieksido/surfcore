# 适配器接口 v0.1（一证、五表、三管）

> 这份文件是**人格内核**与**外部世界**之间的全部约定。
> 不写代码，只写"谁给谁什么、坏了怎么办"——**不懂代码的人也能逐条评审**。
> 与 [设计准则](DESIGN-PRINCIPLES.md) 配套：准则是"为什么"，本文是"是什么"。
>
> 版本：v0.1（2026-11-09）。协议版本号：`1`。
> 状态：**完整可实施**。上一轮自我攻击发现的三个缺口（无法确认的回执、流式内容、打断/取消）已并入本文。

---

## 0. 一句话

**适配器 = 一张身份证 + 五张清单 + 三根管子。**
它一生只做三件事：把外面的事**报上来**（上行）、把内核的话**办下去**（下行）、把办的结果**报回去**（回执）。

```text
        ┌──────── ① 上行管：事件 ────────►
适配器   │                                   人格内核
        ◄──────── ② 下行管：意图 ────────┘
        ┌──────── ③ 回执管：结果 ────────►
```

**内核不认识渠道名**（不知道"QQ"是什么），**适配器不认识记忆**（读不到她的日记）。
两侧只通过事件、意图、回执说话。

## 1. 一证：身份证（注册时交一次）

| 字段 | 人话 | 例子 | 必需 |
| --- | --- | --- | --- |
| 编号 | 全局唯一；**内核用它给上报盖章**（防冒充） | `qq` / `mc-server-7` / `douyin` | ✅ |
| 显示名 | 给人看的 | "QQ" / "我的世界服务器" | ✅ |
| 适配器版本 | 你这版的版本 | `1.4.0` | ✅ |
| **协议版本** | 我们说的是第几版规矩 | `1` | ✅ |
| 质量等级 | 靠谱程度（铜/银/金/铂），用户一眼挑 | `bronze` | 建议 |
| 类别 | 聊天 / 世界 / 游戏 / 传感器 / 只读屏 | `chat` | 建议 |

**类别只给人看。** 内核行为**不许**据类别分支（否则就是"如果是游戏就……"的硬编码，见准则 007）。

## 2. 五张清单

### 2.1 能力表（我能干什么）——整套结构的枢纽

所有渠道差异压进这张表，内核只读它、永不读适配器名字。分五组：

**① 发**

| 字段 | 人话 |
| --- | --- |
| 文字 | 能发吗、最多几字、是否支持粗体/链接/@人 |
| 媒体 | 能发图/语音/视频/表情吗、单个多大、总数多少 |
| 动作 | 能执行游戏/世界指令吗、哪些（**名字由适配器自定，内核不枚举**） |

**② 收**：能收到哪些内容形态（文字、图、语音、视频、世界状态、流）。

**③ 快慢**

| 字段 | 人话 |
| --- | --- |
| 签收期限 | 发出去后多久内必须给回执（毫秒），超时内核判失败 |
| 同步预算 | 最急情况给内核多少时间（游戏回合可能只有 200 毫秒） |
| 典型延迟 | 正常多久能送到（用于预判体验） |

**④ 频率**：每分钟条数、突发上限、并发上限。

**⑤ 特殊能力与边界情况**（这几条是上一轮攻击逼出来的，别删）

| 字段 | 人话 | 为什么必须有 |
| --- | --- | --- |
| 能撤回 / 能编辑 / 有已读回执 | 有就说有 | 没有时内核不许要求 |
| 支持流式 | 实时语音，内容是连续流 | 决定用"单体"还是"流"内容形态 |
| 能被抢话 | 打电话能打断 | 决定要不要发 `cancel` 意图 |
| 刷新延迟 | 电子墨水屏 10 秒才变 | 影响内核的节奏预期 |
| **可能没有身份** | 匿名渠道（传真、匿名投稿） | 否则内核假设"总有个人"，在匿名渠道上崩 |
| 单次收支上限 | 张数 + 总大小 | 这是**适配器侧**的物理上限（用户调档只会在它之下） |

> **"可能没有身份"和"刷新延迟"是最容易被漏掉的两条**，漏了不会立刻报错，只会在接入某个奇怪渠道时突然出问题。

### 2.2 菜单表（用户能改什么）

每个选项必须七件事：**键、显示名、说明、默认值、可选值、代价、分组**。

| 项 | 例子 |
| --- | --- |
| 键 | `video.frames` |
| 显示名 | 视频精细度 |
| 说明 | 每次视频取几张关键画面 |
| 默认值 | 6 帧 |
| 可选值 | 3 帧 / 6 帧 / 逐秒 |
| **代价** | 越细越贵越慢；3 帧最省，但可能漏细节 |
| 分组 | 高级（默认折叠） |

三条硬规矩：
1. **菜单只放"用户偏好"**。凡是"关掉会出事故"的（关白名单、关令牌检查），**不许做成开关**（准则 002）。
2. **界面由内核统一画，配置存在内核**（能导出、能备份、能换机）。适配器只交菜单，**不许自己画界面**——否则能伪造登录框钓鱼（准则 003）。
3. **每加一个开关，记一笔测试账**（准则 005）。

### 2.3 事件表（我会上报什么）

**固定事件（内核认识）**

| 事件 | 什么时候 | 频率 |
| --- | --- | --- |
| `message.received` | 有人说话 | 人类速度 |
| `message.recalled` | 撤回 | 低 |
| `presence.changed` | 上线/离线/进群/退群 | 低 |
| `stream.chunk` | 流式内容片段 | 高 |
| `world.tick` | 世界推进 | **很高**（每秒多次） |
| `world.digest` | 世界摘要（**人话**） | **低**（关键事件 + 定时兜底） |
| `action.result` | 上一个动作的结果 | 中 |
| `decision.requested` | 请求内核决策 | **极低**（必须限频） |
| `adapter.health` | 心跳/健康 | 定时 |

**自定义事件**必须带命名空间：`douyin.gift.sent`、`sts2.card.drawn`。
**内核规则：不认识的类型 → 安静忽略 + 记一行审计，绝不报错、绝不崩。**

### 2.4 意图表（我能执行什么）

| 意图 | 意思 | 必需 |
| --- | --- | --- |
| `say` | 说一句话 | ✅ |
| `send_media` | 发图/语音/视频/表情 | 有能力则支持 |
| `act` | 执行动作（游戏指令） | 游戏类必须 |
| `ask` | 提问并等回答 | 建议 |
| `stay_silent` | **显式沉默**（是一个决定，不是"什么都没发"） | ✅ |
| `close` | 收尾记录（收在哪、下次怎么接） | ✅ |
| `remember` | 提交记忆**候选**（内核决定收不收） | ✅ |
| `cancel` | 取消/打断正在进行的输出 | 支持流式者必须 |
| `mark_read` | 标记已读 | 有能力则支持 |
| `recall` | 撤回自己刚发的 | 有能力则支持 |

两条关键设计：
- **沉默是意图**：不这样，永远查不到"她为什么没回我"。
- **记忆只给候选**：适配器无写入权，记忆只有一个写者（准则 007）。

### 2.5 生命表（活着 + 怎么删）

| 项 | 人话 |
| --- | --- |
| 心跳间隔 / 判死时长 | 多久说一次"我还活着"；内核多久收不到就判定死了 |
| 健康状态 | 正常 / 降级（能收不能发）/ 断开 |
| 启动 | 做什么、超时多久算失败 |
| 停止 | 是否道别、是否保存 |
| **卸载清单** | 删我时清掉哪些配置/状态/订阅，**不许留孤儿** |

## 3. 三根管子

### 3.1 上行：事件信封

| 字段 | 人话 | 可空 |
| --- | --- | --- |
| 事件类型 | 这是什么 | ❌ |
| 渠道 | 哪个会话/频道/世界 | ❌ |
| **说话人** | 谁 | ✅ **可空**（匿名渠道） |
| 时间 | 什么时候 | ✅（空则用内核时间） |
| **编号** | 这条的身份证 | ✅ **可空**（流式内容没有"一条"） |
| 内容 | 文字 / 媒体 / 世界状态 / 流 | ❌ |
| 因果（可选） | 在回哪一条 / 属于哪条流 | ✅ |

**两个"可空"必须显式允许。** 不允许空，内核就会假设"总有个人、总有编号"，然后在匿名渠道和流式语音上崩。

**来源由内核盖章**，不接受适配器自报——否则 A 可以假冒 B 说话（准则 009）。

### 3.2 内容形态（四种，覆盖文字/图/视频/音频/世界）

| 形态 | 用在哪 | 装什么 |
| --- | --- | --- |
| **单体** | 一条消息 | 文字 + 媒体替身 |
| **流** | 实时语音、直播 | 连续片段 + 开始/结束标记，可被 `cancel` 打断 |
| **快照** | 世界状态、游戏局面 | 结构化数据（内核不解释，只存） |
| **摘要** | 战报 | 人话一句话 + 几个关键数字 |

**媒体一律"传替身，不传原件"**（准则 006）：
- 图像 → 缩略图（长边压到 1024 内）+ 一句说明
- 音频 → 文字稿（+ 语气线索）+ 取件码
- 视频 → **3~8 张关键画面 + 文字稿 + 时长** + 取件码
- 取件码只能当**标识**，不能承诺"以后还能取"（很多平台链接有时效）→ **要压就当场压好**

### 3.3 下行：意图

每条意图带：**唯一编号**（防重复）+ 目标渠道 + 内容 + 期限。
**适配器必须幂等**：同一编号收到两次，只许执行一次。

### 3.4 回执：五种结果（不是四种）

| 结果 | 人话 | 内核怎么办 |
| --- | --- | --- |
| 成功 | 送到了 | 记账 |
| 失败 | 出错了 | 重试 / 告诉用户 |
| 做不到 | 我没这能力 | 换个表达 |
| 被限流 | 太频繁 | 排队 |
| **已发出、无法确认** | 像传真：交出去了，不知道对方收没收到 | **既不算成功也不算失败**，按"尽力而为"记账并如实告知 |

第五种必须有：短信、邮件、广播、传真都属于这一类。**少这一种，系统就会说谎。**

回执还带：外部编号（对方的回执 id，可为空）+ 原因 + 建议 + 可重试标记。

## 4. 三方义务

| 内核保证 | 适配器保证 |
| --- | --- |
| 回执在签收期限内到，否则判失败 | 启动成功后上报；停止后不上报 |
| 同一意图编号不重复执行 | 同编号收到两次只做一次 |
| 按声明频率发送，绝不超 | 不伪造来源、不声称未声明的能力 |
| **不认识的事件安静忽略** | 超频时接受削峰 |
| **裁剪时必须告知用户** | 卸载时清干净 |

| 内核**不**保证 | 适配器要知道 |
| --- | --- |
| 顺序 | 多渠道天然并发 |
| 端到端送达 | 回执只代表"平台收下了" |
| 文本格式 | 渲染归适配器 |

## 5. 版本演进规则（让"错了好改"）

1. **只加不改**：加字段可以，改已有字段含义不行。
2. **不认识就忽略**：双方都要容忍新字段/新事件。
3. **协议版本必须带**：内核据此区别对待老适配器。
4. **接口可退役**：老版本至少保留一个大版本，并提前告示。

## 7. 契合 SurfCore 的四件职责（映射关系）

| 内核职责 | 适配器结构里的落点 |
| --- | --- |
| **身份** | 名片（编号，用于盖来源戳）+ 信封（说话人，可为空） |
| **记忆** | `remember` 只给候选 + 信封带来源与可见性 + 媒体替身（省字块） |
| **时机** | 能力表（延迟/频率）+ `world.digest`（低频战报）+ `decision.requested`（限频征询）+ `stay_silent` |
| **预算** | 能力表（收支上限）+ 回执（便于记账）+ 媒体三档（价可预判） |

## 8. 已知取舍（不做，且说明为什么）

| 不做 | 为什么 |
| --- | --- |
| 多租户 / 计费字段 | 那是发行形态的事，不该污染适配器契约 |
| 消息编辑历史 | 极少用到，加了就是长期负担 |
| `act` 的动作名枚举 | 由适配器自定；枚举了就会"每加一个游戏就要改内核" |
| 质量分级的具体标准 | 字段先留，等有 3~5 个真实适配器再定（准则 011 候选） |
