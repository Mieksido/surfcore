# 记忆内核形状（双模块：叙事 + 向量）

> 立文 2026-11-09。来源：用户口述模型 + 代码实测。

> 配套：[适配器形状](ADAPTER-SHAPE.md) · [迁移总计划](MIGRATION-PLAN.md)

## 0. 用户定下的模型（原话整理）

1. 记忆由**两个并行模块**组成：**叙事记忆** 与 **向量记忆**。
2. 用户**可以且仅可以选一个**作为"读取方式"启动。
3. **不管选哪个，另一个也照常存储**——区别只在**调用时用哪个**。
4. 内核要处理"外界调用记忆的申请"：**内核收到外界一条信息，就自动比对记忆库，不需要外界发"请比对记忆"的请求**；
   然后根据检索到的记忆**生成提示词**喂给模型，好了之后**把结果返回给外界**。

## 2. 形状：一个入库层 + 两个读取器 + 一个开关

```text
                    外界来的一条信息（事件）
                              │
                              ▼
                   ┌──────────────────────┐
                   │  入库层（唯一写者）    │   ← 同时喂给两个存储
                   └──────┬────────┬──────┘
                          │        │
              ┌───────────▼──┐  ┌──▼─────────────┐
              │ 叙事存储      │  │ 向量存储        │
              │（衰减/清晰度） │  │（记录 + 索引）   │
              └───────┬──────┘  └──────┬─────────┘
                      │                │
              ┌───────▼──────┐  ┌──────▼─────────┐
              │ 叙事读取器    │  │ 向量读取器      │
              │ 按时间线+重要性│  │ 按语义相似度    │
              └───────┬──────┘  └──────┬─────────┘
                      └──────┬─────────┘
                             │  只走其中一个（memory.mode）
                             ▼
                    ┌──────────────────┐
                    │  记忆块（提示词）  │
                    └────────┬─────────┘
                             ▼
                       提示词 → 模型 → 意图 → 回执 → 外界
```

**四个关键点：**

| # | 关键点 | 为什么 |
| --- | --- | --- |
| 1 | **入库层唯一** | 两个存储都写，但**写的行为只发生在一处**（法则 14：单写者）。否则将来会出现"一边写了另一边没写" |
| 2 | **两个读取器产出不同种类的东西** | 叙事 = 按时间线/重要性分块的"印象"；向量 = 按语义召回的"相关片段"。所以它不是"同一份数据的两种索引"，是**两种视角** |
| 3 | **读取只走一个** | 由 `memory.mode` 决定；另一个存储照常进、照常存 |
| 4 | **对外只有一个接口**：`记忆块` | 上层（模型提示词）不需要知道底下是哪种记忆 |

## 3. 自动流程（内核自己做，外界不用申请）

```text
① 收到事件
② 入库（两套存储都写；这一步永远发生）
③ 判断"此刻需不需要读记忆"        ← 见 §4-A（岔路口）
④ 用当前激活的读取器取一段记忆块
⑤ 拼提示词（人格 + 记忆块 + 未读 + 状态）
⑥ 交给模型，拿到她的决定
⑦ 变成意图交给适配器，收下回执
```

**注意第 ③ 步是新增的、必须显式存在的一步。** 现在的代码里它隐含在"唤醒时拼提示词"里（`src/bridge.js:13808`
`memoryBlock = memoryCardPromptBlock(key)`），没有作为一个独立判断存在。

## 4. 三个必须先定的岔路口（都要你拍板）

### A. 检索时机：每条消息都读，还是只在"要说话时"读？

| 选项 | 现状 | 代价 |
| --- | --- | --- |
| **每条消息都检索** | ❌ 现在**不是**这样 | 每条消息都可能触发一次向量检索（嵌入调用 = 花钱 + 延迟）。群聊刷屏时成本会爆 |
| **只在要回话时检索** | ✅ 现在是这个（唤醒时拼 `memoryBlock`） | 省；但"她记得但没机会说"的情况可能漏掉 |

**我建议保持现状（唤醒时读），但把它显式化成第 ③ 步**——
理由：记忆的价值是"说话时用得上"，不是"每条都算一遍"。而且已有"免费漏斗"（先判断值不值得叫她）可以复用它。

### B. 两份存储，还是一份数据两种视图？

现在是**两份存储**（`memory-card.json` + 向量 JSONL），各自有开关、各自摄取。

| 选项 | 好处 | 坏处 |
| --- | --- | --- |
| 维持两份 | 已经跑通；各自可独立开关 | **同一件事存两次**：删除/遗忘/纠正要同步两处，不同步就"一边记得一边忘了" |
| 一份原始 + 两种视图 | 单写者彻底；删一次全删 | 要重写摄取与存储；向量要现算 |

**我建议：短期维持两份（迁移成本低），但把"删除/遗忘"做成入库层统一动作**，保证两边同步。长期再考虑合并。

### C. 两个读取器要不要"统一输出格式"？

叙事产出的是分区块的"印象"，向量产出的是"相关片段列表"。如果两者格式不同，
上层（拼提示词的那段）就得知道"现在是哪种模式"——**这又把渠道式判断带进内核了**。

**我建议：两个读取器都输出同一个东西——"一段可直接拼进提示词的文字 + 它引用了哪些记录"。**
这样上层完全不需要知道模式。

## 5. 目的机制怎么吃记忆（衔接点）

现在 `purpose-engine` 的 `collectMaterials`（514-739）**直接读记忆的原始形状**（recent/convo list）。
这与"记忆有统一读取接口"冲突。

**建议**：目的机制通过**同一个读取器**拿素材，而不是直接读存储。
这样"换记忆方式"时，目的机制自动跟着变，不需要改它。

## 8. 决策记录与后果（2026-11-09 用户拍板）

### A. 检索时机：**只在她做出行为前读取**

不是每条消息都读，而是"要行动了才读"。

**后果（必须写进架构）：**
1. **读取器由"行为准备"调用，不由"事件入口"调用。** 事件入口只负责入库（永远入库）。
2. **读取延迟直接压在"她要开口"的那条路径上**。所以：
   - 向量必须**入库时就算好**（不能读的时候现算）；
   - 读取时的查询向量仍要算一次 → 这是唯一不可避免的延迟，要能容忍或缓存（见 §10 待定）。
3. 好处：刷屏的群不会因为"每条都检索"而烧钱——**这正是现有代码的做法**（唤醒时拼记忆块）。

### B. 两种存储都留，但**定位完全不同**（这条最重要）

用户原话要点：**向量记忆是以后长期要用的；叙事记忆效果太差，迟早被淘汰；现在没从架构里删掉，只是照顾部分用户。**

**这不是"两个并列模块"，而是"一个未来 + 一个兼容层"。** 后果：

| 后果 | 具体做法 |
| --- | --- |
| **叙事读取器标记为"可退役"** | 文档与代码里明确它是兼容层；将来整块删除不许影响内核 |
| **接口必须稳定到"删掉叙事不影响内核"** | 内核只依赖"读取接口"，绝不依赖叙事的实现细节 |
| **不要把精力投在叙事算法优化上** | 它现在的衰减/评分逻辑**照搬即可**，不再改进（它要被淘汰） |
| **投资方向明确指向向量** | 向量读取器是主路径；叙事是用来"照顾老用户/兜底"的 |
| **数据要能迁移** | 叙事 → 向量 的迁移路径要留得出来（不要求现在实现） |

> ⚠️ 这条会改变迁移优先级：**记忆单元里，向量侧要做得扎实，叙事侧只要"能用、能删"**。

### C. 读取器输出格式：**统一**

两个读取器都必须返回**同一个东西**：

```
一段可以直接拼进提示词的文字　+　它引用了哪些记录
```

这样上层（拼提示词的、目的机制的）完全不需要知道"现在是哪种模式"。**否则又会长出 `if (mode === 'vector')`。**

## 9. 叙事记忆的「行为清单」（迁移第 ① 步，逐条来自代码）

| # | 行为 | 代码位置 |

| 1 | 清晰度五档，**每天最多降一档**（渐渐模糊，不一次消失） | `applyDailyDecay` 1625-1667 |

| 4 | **主人重要记忆保底 55**，永不遗忘 | `ownerImportant` + `targetClarity` 1612 |
| 5 | 最近 N 天保底"清楚" | `targetClarity` 1613 |
| 6 | 超过遗忘天数 + 重要度 < 50 + 非保护 → 遗忘（移入全量卡） | `targetClarity` 1603-1605 |
| 7 | **第一句主人消息钉成永久锚点**（重要度 100、pinned） | `scoreMemory` 1201-1205 |
| 8 | 重复记录只刷新"最后出现时间"，**不重复占容量** | `addMemoryRecord` 1292 |

| 11 | **敏感记忆永不进提示词**（只给管理员看） | `visibleFor` 1812 |
| 12 | 群里不见私聊记忆；跨群只看"同圈" | `visibleFor` 1818-1824 |
