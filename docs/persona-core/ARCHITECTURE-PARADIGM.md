# 架构范式（当前版本）

> 这份文档描述**新架构现在长什么样**，是"范式"而不是"计划"。
> 与旧 SurfCore 的关系：**旧代码是需求，不是骨架**（准则 000）——功能照搬，结构重长。
> 最后更新：2026-11-10。所有数字都可用 `node tools/run-all.mjs` 复算。
> 配套：[设计准则](DESIGN-PRINCIPLES.md) · [架构法则](ARCHITECTURE-LAWS.md) · [迁移总计划](MIGRATION-PLAN.md)

---

## 0. 一句话

> **一个人格核心（黑框）+ 一个适配器运行时（红框）＝ SurfCore 本体。**
> 外面挂着一排**平台包**（绿框），每个包是一个可打包带走/导入的目录。

### 0.1 本体的边界（法律边界，也是架构边界）

| 属于本体 | 不属于本体 |
| --- | --- |
| `kernel/` 人格核心 | `packs/` 平台包（**独立发布**，本体分发包里**一个都不带**） |
| `runtime/` 适配器运行时 | `tools/` `app/` `docs/` `contracts/`（开发期/文档） |
| `shared/` 地基（52 行纯时间函数） | 任何第三方运行时、二进制、依赖目录、凭据 |

**判据**：`node tools/core-check.mjs` 必须 exit 0——
核心无二进制、不 import 扩展、无渠道名、不含平台包。
平台包单独出包：`node tools/pack-build.mjs --all` → `dist/<名字>-<版本>.zip`（只含运行期代码，不带测试）。

三层各有各的秘密，谁也不许越界：

| 层 | 它知道什么 | 它不许知道什么 |
| --- | --- | --- |
| **内核**（人格核心） | 她是谁、记得什么、想做什么、什么时候说、能花多少 | **任何平台**（不认识"QQ"，也不认识渠道名） |
| **运行时**（大适配器） | 怎么把消息安全地运过去 | 人格、记忆、以及**任何一个平台** |
| **平台包** | 那个平台的规矩 | 人格、记忆、内核的任何内部 |

## 2. 黑框：人格核心的九件套

| # | 部件 | 职责 | 不做 |
| --- | --- | --- | --- |
| 1 | **身份**（`kernel/support`） | 她是谁、谁是主人、怎么称呼；公开版受字数限制 | 不读渠道 |
| 2 | **记忆**（`kernel/memory`） | 入库（永远发生）→ 双存储 → 选一个读取器 → 统一记忆块；衰减/遗忘/归档；媒体库 | 不做表达、不发消息 |
| 3 | **目的**（`kernel/purpose`） | 驱动向量、目标假设、观察账本、闭环反馈；**投递即占次数** | 不抢被叫到的话 |
| 4 | **注意力**（`kernel/attention`） | 唤醒分级、合批、群分层、鱼群、刷屏指令 | 不产生回复 |
| 5 | **表达**（`kernel/expression`） | 提示词组装、模型端口、工具面（她的手）→ 意图 | 不直接发消息 |
| 6 | **语音**（`kernel/voice`） | 用不用语音、本地/云端路由、长度频率闸门、库校验、失败分类 | **不负责把音频送出去** |
| 7 | **预算**（`kernel/support`） | 按已发生成本记账；超了拒绝 | 不设"口味上限" |
| 8 | **审计**（`kernel/support`） | 只追加；谁在何时做了什么、被谁拒了 | 不改任何数据 |
| 9 | **设置**（`kernel/settings`） | 菜单 → 统一表单；值收敛；可导出/导入 | 不自己画界面 |

### 2.1 记忆的结构（两条线、两张卡）

```
记忆
├─ 叙事记忆 ──────────────── 与向量**同级**
│   ├─ 衰减记忆卡            会忘、会模糊（clarity 五档，每天最多降一档）
│   └─ 全量记忆卡            入库即留底、只追加（append-only，永不删改）
└─ 向量记忆 ──────────────── 与叙事**同级**

入库：三处一起写（全量卡 / 衰减卡 / 向量库）
读取：同一时刻只走一条（memory.mode）
```

| 规矩 | 为什么 |
| --- | --- |
| **双存储，不是投影** | 两条线各存一份；不是"一份数据两种看法" |
| **退化 ≠ 消失** | 遗忘只是"从衰减卡里出去"，全量卡里一直都在 |
| **读只走一条** | 同一时刻只有一个记忆被读到，避免两套记忆互相干扰 |
| **两条线共用同一套可见性** | 政策只有一份（`identity.js` 的 `allowed`），换线不换政策 |

**全量卡是设定，不是合规开关**：它本来就该是全量。要满足删除义务，只能靠"别把
原文写进不该写的地方"，不能靠"让全量卡少记一点"。

**贯穿件**：`kernel/store/persist.js`（原子写 + 备份 + 读坏降级）、`kernel/index.js`（总装）。

### 一次反应的固定顺序

```text
① 入库（永远发生，哪怕不醒）
② 要不要行动（注意力）
③ 读记忆（只在这时读，用当前激活的读取器）
④ 表达（提示词 → 模型 → 工具面 → 意图）
⑤ 目的（没被直接叫到时才考虑主动说）
⑥ 交给运行时
```

## 3. 红框：运行时（管道，六件事）

| 管道职责 | 做什么 |
| --- | --- |
| **槽位校验** | 包没填满四块（身份/能力/菜单/生命）→ 拒绝装配，不带病运行 |
| **来源盖章** | 上报事件的来源戳由运行时改写，包不能自称是别人 |
| **幂等** | 同一意图编号第二次只回执、不重发 |
| **能力门** | 纯文本渠道收到"发媒体"→ 直接回"做不到" |
| **回执包装** | 自动补编号与时间；非法状态兜底；抛异常包成结构化失败，不冒泡 |
| **媒体验收** | 数量/体积超限就削掉并记 warn（不硬塞，也不悄悄丢） |

**三条硬约束**（防的正是 `bridge.js` 那种腐化——它本来是中间层，最后吃掉了判断力）：

1. 只做管道，不做判断（"该不该发"是内核的事）
2. 不碰记忆、不认识人格
3. 输入只有事件、输出只有意图，没有第三条捷径

另有 **包宿主**（`runtime/host.js`）：发现/校验/安装/启用/卸载（见 §7）。

## 4. 地基：`shared/`

`shared/time.js` —— 唯一日界、安静时段、时间窗。

**为什么单独一层**：内核要用（衰减/日界），平台包也要用（生物钟/安静时段），
而**平台包不许 import 内核**。所以把最稳定、最无依赖的东西放最底层。

## 5. 三种消息，只有这三种

| 消息 | 方向 | 内容 |
| --- | --- | --- |
| **事件** | 包 → 内核 | 谁 / 哪个频道 / 什么时候 / 发生了什么 / 内容（文本·图像路径+说明·音频路径+说明·结构化状态） |
| **意图** | 内核 → 包 | 说 / 发媒体 / 做 / 问 / **沉默** / 收尾 / 记住（候选）/ 取消 |
| **回执** | 包 → 内核 | 办到了 / 失败 / 做不到 / 被限流 / **已发出无法确认** |

两个必须允许为空的字段：**说话人**（匿名渠道）、**编号**（流式内容）。

## 6. 一个能力怎么横跨两层（以语音为例）

```text
        她的决定                          真的送出去
   ┌──────────────────┐            ┌──────────────────┐
   │ 内核 kernel/voice │  意图带     │ 平台包            │
   │ 用不用/本地还是云端│ voice 字段 ►│ QQ 语音条 / 桌宠播放│
   │ 闸门/库校验/失败分类│           │ 只管把字节发出去   │
   └──────────────────┘            └──────────────────┘
```

**同一条规矩适用于一切跨层能力**：判断力在内核，手艺在包里。

## 7. 平台包 = 一个目录（可 zip 带走）

```text
packs/qq/
├─ pack.json      ← 唯一真相：发布人 / 名字 / 版本 / 协议 / 入口 / 权限声明 / requires
├─ index.js       ← 四块声明 + 收(attach/push) + 发(send)
├─ onebot.js      ← 私有模块（协议解析与发送）
├─ receiver.js    ← 私有模块（WS 连接/心跳/重连）
└─ text.js        ← 私有模块（CQ 转义与拆条）
```

### 7.1 网关不由包提供（重要）

QQ 包只说 **OneBot v11 协议**，**不自带网关、不随包分发**：

| 项 | 归属 |
| --- | --- |
| 协议实现（事件解析、发送、重连） | **包里** |
| 网关进程本身（连 QQ 的那个东西） | **用户自备**，`wsUrl`/`httpUrl` 由用户填 |
| 具体网关软件（含 SnowLuma） | **不在仓库、不进 zip、不做安装器** |

理由：那类网关是第三方专有运行时，许可不允许随本项目分发（见 `docs/legal/third-party/`）。
所以包里只写 `requires: ["onebot11-gateway（用户自备）"]`，**协议是开放的，软件不是我们的**。

没配 `wsUrl` 时包仍可用：**只发不收**，并在日志里说清（不静默降级）。

| 能打包带走 | 不能带走 |
| --- | --- |
| 包目录本身（含私有模块） | 内核、运行时、地基（那是本体） |
| — | 用户配置、记忆、媒体原件（属于用户，在内核侧） |

**导入流程**：`zip → 解压 → installFrom() → 包内容闸门 + 清单校验 + 与代码自洽检查 → 装进 packs/ → 写 _origin.json → 默认关闭 → 用户打开（enablePack）→ loadEnabled()`

### 7.2 三个"证据"文件（不是承诺，是可复核的记录）

| 文件 | 谁写 | 内容 | 用途 |
| --- | --- | --- | --- |
| `packs/<名字>/_origin.json` | `installFrom()` | 发布人/名字/版本/安装时间/来源（相对路径）/清单 sha256/trust/requires | 被质疑时能证明"这个包从哪来、装的时候是什么" |
| `packs/_policy.json` | 用户 | `allowedPublishers` / `requireAckForUnverified` / `notice` | 决定"谁的包算受信" |
| `state/.../packs-state.json` | 宿主 | 哪些包已启用 | 默认全关，必须显式打开 |

**启用闸门（fail-closed）**：未背书的发布人 → `enablePack()` 返回 `pack.needs-ack`，
必须带 `ack: true` 才放行，并且明确告知"它会跑在你的进程里"。

### 7.3 包内容闸门（出站与入站同一份规则）

```
runtime/pack-rules.mjs           ← 唯一规则源（6 条）
   ├─ tools/pack-check.mjs       ← 出站：发包前拒绝
   ├─ tools/pack-build.mjs       ← 出站：打包时先过它，再压 zip（排除 *.test.mjs）
   └─ runtime/host.js
        ├─ installFrom()         ← 入站：装包前拒绝（不落盘）
        └─ loadPack()            ← 入站：加载前再查（手工拷进来的也逃不掉）
```

规则只做机械判定（看路径，不读内容、不执行）：原生二进制/启动器 · 依赖目录 ·
第三方运行时 · 锁文件 · 凭据与运行期数据 · 版本库元数据。

### 7.4 AI 标识：事实在内核，形式在包

| 层 | 给什么 |
| --- | --- |
| **内核** | `intent.aiGenerated = true` + `intent.label = 'AI 生成'`（只给 say / send_media，沉默不带） |
| **平台包** | 决定怎么让它可见：文本前缀 / 语音提示音 / 图片角标 |

关闭标识必须显式 `aiLabeling: { enabled: false }`，并会写一条审计（不能悄悄关）。

**三条纪律**（都有测试）：

1. **清单与代码必须自洽**：清单说 `acme/demo 1.0.0`，代码里三处也必须一样，否则拒绝（防"包里说自己是官方"）
2. **卸载不删除**：移进 `_removed/`，可恢复
3. **装进来 ≠ 打开**：默认全关，必须显式启用

## 8. 十条不变量（改代码前先看）

| # | 不变量 |
| --- | --- |
| 1 | **入库永远发生**——哪怕这次不醒，也先记下来 |
| 2 | **记忆只有一个写者**（内核）；包只能提交候选 |
| 3 | **只有在要行动时才读记忆**（不是每条消息都检索） |
| 4 | **两个读取器输出同一种东西**：`{ text, refs, mode }`（实测：叙事与向量返回的键完全一致） |
| 5 | **忘掉 ≠ 消失**：遗忘进 append-only 档案，不进提示词 |
| 6 | **投递即占次数**（模型回合已经花钱了） |
| 7 | **沉默是一个决定**，必须产出 `stay_silent` 意图，可审计 |
| 8 | **失败必须可见**：读坏降级、专注拦截、超时"无法确认"，都不许假装成功 |
| 9 | **超时不许当失败重发**（可能已经发出去了） |
| 10 | **内核里不许出现渠道名**（有自动检查） |
| 11 | **媒体编号只在内存里**：交给包之前必须换成"路径 + 说明"（包不认识媒体库） |
| 12 | **网关不随包分发**：协议开放，软件用户自备

## 9. 适应度函数（免疫系统）

`node tools/fitness.mjs` —— 把架构规则做成**会变红的检查**：

| 检查 | 规则 |
| --- | --- |
| 渠道名 | `kernel/` 与 `runtime/` 里不许出现渠道名字面量 |
| 依赖方向 | 内核不许依赖运行时/包；运行时不许依赖包/内核；包不许依赖内核；`shared/` 谁也不许依赖 |
| 可测性 | 每个有代码的层都必须有 `*.test.mjs` |

**日常入口**：`node tools/run-all.mjs`（跑全部测试 + 适应度函数）。

> 这才是"给架构装免疫系统"的真正含义：**让破坏规则这件事不可能悄悄发生。**

| 缺口 | 卡在哪 |
| --- | --- |
| QQ 真连网关 | 需要网关在线 + 地址/令牌 |
| B站 网络调用 | 需要真登录态（cookie） |
| 语音合成 | 需要本地/云端语音服务（内核只做决策，合成归服务） |
| 设置界面 | 需要 DSH 宿主画（`kernel.settings.model()` 已能直接渲染） |
| 桌宠长轮询通道 | 仓库外的桌宠工程 |
| 全量记忆检索界面 | 界面层 |
| 单写者锁的时机 | 现在只在 `save()` 时加锁；`load()` 不加（只读不需要） |

## 12. 怎么验证

```powershell
npm run test:arch              # 全部测试 + 适应度函数（应 exit 0）
npm run test:arch:fitness      # 只跑架构检查

npm run surfcore               # 看系统状态（包清单 / 内核快照 / 检查）
npm run surfcore:boot          # 装载所有已启用的包并跑起来
npm run surfcore:chat          # 只跑终端包，直接跟她说话

node app/surfcore.mjs enable qq    # 打开一个包（装进来 ≠ 打开）
node app/surfcore.mjs disable qq   # 关掉
```

**状态目录**：默认 `state/persona-core/`（已被 `.gitignore` 忽略），可用 `--state <目录>` 覆盖。
